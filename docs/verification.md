# 验证记录

日期：2026-10-02。当前版本使用 Telegram 按钮内的 Samsung 临时直链，失效后手动刷新。

## 当前行为

- `/dl` 或直接发送包名：查询版本、申请下载授权、获取更新说明，将原“正在查询”消息编辑为带“下载”和“刷新”按钮的卡片。临时 URL 只出现在“下载”按钮中。
- 未指定地区时先尝试 US，元数据查询或下载授权失败后尝试 CN；显式指定 US/CN 不切区。返回卡片显示最终选中的地区和版本。
- 应用名和版本在卡片顶部加粗，版本代码直接显示，地区、大小和包名常显，更新说明折叠；订阅更新标题带“有更新”。进度消息本身变成卡片，始终使用同一个消息 ID；底部提示“链接约 10 分钟有效，过期请点刷新”。
- “刷新”通过 Telegram 回调重新查询并授权，同时更新原卡片的版本信息和下载按钮，不新增消息。应用记录保存在 SQLite，刷新不创建订阅。
- `/sub` 只保存订阅；后台检查只查询版本和更新说明。订阅回执和更新通知只有“获取下载链接”按钮，点击后才申请授权，并将同一张卡片更新为“下载”和“刷新”两个按钮。
- bot 和诊断脚本均不下载 APK，不请求 CDN 文件或上传 Telegram 附件。临时链接不写入 SQLite 或日志。
- 使用 Telegram 官方 API 和长轮询。部署只需 `BOT_TOKEN`、`OWNER_ID`；Compose 只有一个 bot 容器，不发布端口。
- 已移除 HTTP 跳转服务、签名入口、域名/监听配置、Caddy 示例、本地 Bot API 容器，以及完整 APK 下载、Manifest 解析和相关依赖。

- 当前离线测试：**176 passed**；Ruff 静态检查和格式检查通过。覆盖来源解析、地区选择、错误处理、Samsung URL 校验、权限、订阅持久化、通知送达状态、Telegram 发送与回退，以及启动和停止流程。

- 启动测试拦截生产轮询，并禁止绑定 socket；确认不需要公网地址、不监听端口，订阅调度和 SIGTERM 停止仍工作。
- Compose 使用合成的两项配置校验：只有 `apkdl-bot`，没有发布端口，`/data` 持久化。
- 本轮未发送真实 Telegram 消息，也未在手机上下载 APK。

## 来源实测记录

更新日期使用同包名、同版本 CN 网页详情的 `modifyDate`，与更新说明共用一次请求；不会把 CN 日期用于 US 版本，也不会用抓取时间替代。实测三星生活助手 9.4.02.7 返回 `2026.08.25.`，卡片显示 `更新时间：2026-08-25`。缺失、不匹配或非法日期显示“暂无数据”，不影响下载。历史缓存无此字段仍可读取。

手动查询与后台检查均缓存应用元数据；订阅确认及列表显示同包名最近抓取到的应用名，不为显示名称额外请求商店。缓存元数据不会把订阅标为已通知，临时下载 URL 仍不入库。

## 原位编辑与 CDN 403 排查

官方 Telegram Bot API `Client::process_edit_message_text_query` 支持 `editMessageText` 传入 `rich_message`，可同时更新卡片和 `reply_markup`。代码使用这一已核对的接口；明确不支持富消息时，回退为相同消息 ID 的 HTML 编辑。`message is not modified` 视为内容已经一致，不另发消息。

新增测试覆盖初次查询只发一条进度消息并原位编辑、订阅回执及通知的单按钮转双按钮、版本与直链同时更新、HTML 编辑回退、编辑结果未确认时不重复发送，以及回调过期不撤销已完成的编辑。尚未用用户当前 Token 进行实时消息编辑验证。

用户 403 截图中的 `px-time` 对应北京时间 18:25:58，报错时间为 18:27:10，已晚 72 秒。重新申请的同应用链接，其 `px-time` 比授权响应时间约晚 10 分钟；用普通浏览器和 bot 请求头分别检查，均返回 HTTP 200 和 APK 内容类型。诊断使用流式请求并立即关闭，未读取响应正文或保存 APK，也未打印签名 URL；这些请求只用于本轮排障，没有加入 bot 运行流程。

上述证据符合旧链接过期。卡片使用用户要求的简短“约 10 分钟”提示，不显示精确到期时间；最终有效期由 Samsung 决定。手机使用刷新后的链接仍需用户验证。

## 下载文件名与本轮优化

用户希望下载文件名为“应用名_版本号”。实测结论：直链方案做不到。

- CN 授权链接在 `cdnet-dn.galaxyappstore.com`（网宿 CDN，源站 S3），响应固定为 `Content-Disposition: attachment; filename=App_20260924084213356.apk`。US stub 链接在 `cflare-dn.gw.samsungapps.com`（Cloudflare，源站 S3），固定为 `prePost_20260917014102504.apk`。
- 追加 `response-content-disposition`、`filename`、`attname`、`fname`、`download` 或 `#文件名` 均返回 200，文件名不变；改动路径返回 403。
- 自定义文件名只能让 APK 经过中转：Bot API 上传上限 50 MB（瑞幸 128 MB），VPS 或 Cloudflare Worker 中转需要域名并经手 APK，均与当前设计冲突，未采用。诊断只读响应头后立即关闭，未保存 APK。

同轮优化：

- US/AUTO 下载复用选定版本时那次 stub 应答中的 URL，不再重复请求 stub。实测 Samsung Notes（AUTO→US）只请求 1 次 stub 加 1 次详情；瑞幸 AUTO 回退 CN、显式 CN 仍正常，链接均返回 200。
- 订阅只在版本代码高于上次通知时推送。AUTO 因 US 偶发失败回退 CN、同一版本来回切换，或版本回退，不再误报“有更新”。旧数据的 `last_notified` 格式不变，直接兼容。
- 启动约 1 分钟后先检查一次，再按 `CHECK_INTERVAL` 间隔检查，频繁重建容器不会推迟检查。
- 刷新失败且回调已过期时，在原卡片下回复失败原因，不覆盖原卡片；成功或结果不确定时行为不变。
- 详情链接接受 `?session_id=…` 等查询参数和片段，只取路径中的包名；端口、多级路径等仍拒绝。
- `/unsub <包名>` 不写地区时取消该用户该包名所有地区的订阅；写明地区时只取消对应地区。

## 富文本与其余优化

参考 kdbot 的富文本做法调整卡片，块结构与 kdbot 线上使用的一致（`table`、`buttons`、`copy_text`、行内 `code`）：

- 下载卡片的版本代码、更新日期、地区、大小、包名改为无边框紧凑两列表，包名用代码样式；HTML 回退版仍是“标签：值”逐行显示。
- 行内键盘改为卡内 `buttons` 块并清空 `reply_markup`，避免按钮出现两次；外跳下载为 `success`，回调为 `primary`。服务端以 400 明确拒绝 `buttons` 块时，同一请求改用“卡片 + 行内键盘”重试一次，并在本次运行内记住。
- 下载卡片新增“复制文件名”按钮（`copy_text`），内容为“应用名_版本号.apk”，去掉 `\ / : * ? " < > |` 等路径字符；两种形态都有此按钮。
- `/help` 的命令改为两列表，补充说明进页脚；订阅确认、`/list`、`/status`、白名单卡片使用加粗应用名和代码样式的包名/ID。
- 新增离线测试按 Bot API 形状校验所有卡片和按钮块，覆盖按钮块被拒后的回退和记忆。
- Galaxy Store 自身在 US stub 与 US 网页上的名称都是 `[260921] GALAXY Store 9CR Update -  US`；CN 网页为“三星应用商店”。仅当名称以 `[数字] ` 开头时改用 CN 名称，版本标识不变。
- Docker 镜像改为 `apkdl`（UID 10001）运行。在本机实际构建并验证：旧版 root 写入的 `app.db` 交接后可读写，Python 以 PID 1 运行（SIGTERM 处理不变），只读挂载时提示并回退为 root。构建验证时仅为本沙箱代理临时注入 CA，仓库 Dockerfile 未包含此项。

尚未在真实 Telegram 客户端确认表格、卡内按钮颜色和复制按钮的显示效果，需部署后查看。
