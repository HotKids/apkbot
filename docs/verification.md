# 验证记录

日期：2026-10-02。当前版本使用 Telegram 按钮内的 Samsung 临时直链，失效后手动刷新。

## 当前行为

- `/dl` 或直接发送包名：查询版本、申请下载授权、获取更新说明，将原“正在查询”消息编辑为带“下载”和“刷新”按钮的卡片。临时 URL 只出现在“下载”按钮中。
- 未指定地区时先尝试 US，元数据查询或下载授权失败后尝试 CN；显式指定 US/CN 不切区。返回卡片显示最终选中的地区和版本。
- 应用名和版本在卡片顶部加粗，版本代码直接显示，地区、大小和包名常显，更新说明折叠；订阅更新标题带“有更新”。进度消息本身变成卡片，始终使用同一个消息 ID；底部提示“链接约 10 分钟有效，过期请点刷新”。
- “刷新”通过 Telegram 回调重新查询并授权，同时更新原卡片的版本信息和下载按钮，不新增消息。应用记录保存在 SQLite，刷新不创建订阅。
- `/sub` 只保存订阅；后台检查只查询版本和更新说明。订阅回执和更新通知只有“获取下载链接”按钮，点击后才申请授权，并将同一张卡片更新为“下载”和“刷新”两个按钮。
- bot 和诊断脚本均不下载 APK，不请求 CDN 文件或上传 Telegram 附件。临时链接不写入 SQLite 或日志。
- 使用 Telegram 官方 API 和长轮询。部署只需 `BOT_TOKEN`、`OWNER_ID`；Compose 只有一个 bot 容器，不发布端口。
- 已移除 HTTP 跳转服务、签名入口、域名/监听配置、Caddy 示例、本地 Bot API 容器，以及完整 APK 下载、Manifest 解析和相关依赖。

## 原位编辑与 CDN 403 排查

官方 Telegram Bot API `Client::process_edit_message_text_query` 支持 `editMessageText` 传入 `rich_message`，可同时更新卡片和 `reply_markup`。代码使用这一已核对的接口；明确不支持富消息时，回退为相同消息 ID 的 HTML 编辑。`message is not modified` 视为内容已经一致，不另发消息。

新增测试覆盖初次查询只发一条进度消息并原位编辑、订阅回执及通知的单按钮转双按钮、版本与直链同时更新、HTML 编辑回退、编辑结果未确认时不重复发送，以及回调过期不撤销已完成的编辑。尚未用用户当前 Token 进行实时消息编辑验证。

用户 403 截图中的 `px-time` 对应北京时间 18:25:58，报错时间为 18:27:10，已晚 72 秒。重新申请的同应用链接，其 `px-time` 比授权响应时间约晚 10 分钟；用普通浏览器和 bot 请求头分别检查，均返回 HTTP 200 和 APK 内容类型。诊断使用流式请求并立即关闭，未读取响应正文或保存 APK，也未打印签名 URL；这些请求只用于本轮排障，没有加入 bot 运行流程。

上述证据符合旧链接过期。卡片使用用户要求的简短“约 10 分钟”提示，不显示精确到期时间；最终有效期由 Samsung 决定。手机使用刷新后的链接仍需用户验证。
